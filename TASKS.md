- **Label Printing module (HACCP food-safety labelling)** — full plan in [docs/label-printing-plan.md](docs/label-printing-plan.md). Chef prints date/use-by labels for Market List ingredients, prep items, recipes, production recipes and custom items from a laptop in the outlet. Decisions locked during scoping (2026-07-30): browser kiosk printing via Chrome `--kiosk-printing` (NO PrintNode — the printer is attached to an always-on outlet PC, so there's nothing remote to solve; PrintNode columns stay nullable in the schema behind a two-method driver interface). Tablets + Bluetooth printers were evaluated and REJECTED: Web Bluetooth has never shipped in Safari so iPad is a hard blocker, Android Chrome supports BLE/GATT only and can't speak the Bluetooth Classic SPP most thermal printers use, and Bluetooth Classic holds one connection at a time so multiple tablets fight over one printer. If chefs later demand tablets, every outlet already has an always-on POS/back-office PC to host a PrintNode bridge — that's a client install plus flipping `label_printers.driver`, no new hardware and nothing above the transport layer moves. Other decisions: one Blade partial rendered two ways (`LabelRenderService::html()` for browser print + designer preview, `::pdf()` via dompdf for archive/reprint) which constrains the label markup to dompdf's CSS subset — absolute positioning only, no flex/grid; shelf life as a storage-state matrix (ambient/chilled/frozen/thawed/opened/cooked) defaulted at *category* level with per-item override, resolving item → category → legacy `recipes.shelf_life_value` → manual entry flagged `manual_expiry`; use-by rounds to end-of-day 23:59, company-configurable; staff attribution by tapping your name from the outlet employee list, no PIN; print sets ("Chiller 1", "Grill Station") are outlet-owned with per-line label type and copies, always open a review checklist before printing, and are named `LabelSet` in code because `OutletGroup` already exists; deliberately NOT reusing `RosterStation`. Four phases — (1) migrations, models, render service, shelf-life matrix + bulk-edit grid, printers, settings, permissions (`labels.print` / `labels.manage` / `labels.view_log`), 5 stock templates; (2) print screen, print sets, review screen, batch + print-log writes; (3) template designer with mm canvas + calibration label; (4) expiring-today dashboard off `label_prints` feeding one-tap into `WastageRecord`. Out of scope for v1: allergens, nutrition, QR traceability, barcodes, Production Order / GRN entry points, ZPL, PrintNode, consumable tracking, per-label metering. BLOCKED on two answers before phase 3: which physical label sizes ship as designer presets (50×25, 56×31, 76×50?), and which printer make/model outlets are buying (Brother QL and Zebra have different unprintable margins and the calibration tool needs its target).

- 2026-08-06 — **Payroll phase 2: year-to-date, and the real LHDN MTD formula for PCB.** This closes the gap flagged when statutory went in — PCB was annualising the current month because the proper formula needs a payroll history the system did not keep.
