## 1. Procurement / Purchasing

**Flow as implemented:** PR → PO → DO → GRN → Invoice (+ Credit/Debit Notes). Standard mode starts at PO; CPU mode starts at PR and routes through consolidation. PO approval can silently branch three ways (email supplier / auto-generate DO+GRN / "sent to purchasing team") depending on hidden company flags.

### Pain points
1. **Unexplained abbreviations everywhere** — PR, PO, DO, GRN, STO, UOM, "Par Level", "Balance" appear with no expansion or tooltip.
2. **Inconsistent status vocabulary** — the same record reads "Submitted" as a badge but filters under "Pending Approval"; `sent` is labelled "Processing" in one place and not another (po-table vs index filters).
3. **"Convert to PO/DO" assumes domain knowledge** — the only next-step cue after PR approval is a small icon with a tooltip.
4. **Invisible automation** — approving a PO may silently create DO+GRN or email the supplier; the only feedback is a 3-second toast, then the record "vanishes" from the list.
5. **Dense, finance-oriented forms** — PO form shows Par Level, Balance, 4-decimal unit cost, tax breakdown to a chef reordering onions.
6. **Dead-end empty states** — "No purchase requests found" with no CTA or explanation.
7. **Icon-only action rows** — 4-6 tiny colored SVGs per row, distinguishable only by tooltip (mobile cards are clearer than desktop!).
8. **Two receiving screens** (ReceiveForm vs GrnReceiveForm) both titled "Confirm Receipt" with no explanation of which to use.
9. **AI invoice flow leaks accountant concepts** — "Match confidence 62%", "Exceptions" with severity levels.
10. **Naming drift** — nav "Orders & Requests" vs page "Purchasing" vs "Procurement Invoices" vs "Find Suppliers".

### Top improvements (ranked value ÷ effort)
1. Expand every acronym on first use — "Requests (PR)", "Orders (PO)", "Deliveries (DO)", "Goods Received (GRN)" + a "?" popover per tab. *Copy only.*
2. Status stepper/timeline on each document: Request → Approved → Ordered → Delivered → Received.
3. Replace 3-second toasts with a persistent "what happens next" panel after submit/approve/convert.
4. Labeled action buttons on desktop (adopt the mobile card pattern).
5. Meaningful empty states with a primary CTA and one-sentence purpose.
6. Unify status labels between badges and filters (one shared helper).
7. Clarify the two receiving paths; when a GRN exists, route the PO "Receive" action to it.
8. "Advanced" toggle hiding Par Level/Balance/4-dp cost/tax for non-purchasing roles; default unit cost from last purchase.
9. Explain "Convert to PO/DO" inline with outcome-stating confirms.
10. Plain-language the AI invoice exceptions ("Price is higher than the PO — check before approving").

## 2. Central Kitchen

**Flow as implemented:** outlet PRs come in as Prep Requests (Approve → Fulfill auto-transfers stock out); production orders go draft → scheduled → in_progress (Execute screen) → completed (stocks the KITCHEN, not outlets). Recipes carry full costing/margin data.

### Pain points
1. ✅ **The Complete confirmation lied** — claimed it "creates outlet transfers"; it only stocks kitchen inventory. *Fixed: dialog now says output goes to kitchen stock and ships via prep requests.*
2. **Tiny touch targets** — row actions are ~11px text links 8px apart, on kitchens' greasy tablets, with Delete adjacent to Deactivate.
3. **Fulfill has no confirmation** — it ships stock and deducts inventory silently; success toast hides in 3 s.
4. **Accounting jargon for cooks** — Yield Variance %, Cost/Unit, Margin % surfaced on screens line staff use.
5. **Dense unexplained statuses** — 5 order + 5 request states as small pills; "scheduled" means "press Start" but nothing says so.
6. **Two overlapping navigation systems** — sidebar groups AND in-page tabs cover the same content; sidebar "Production Orders" opens the *create form* while the tab shows the *list*.
7. **Silent workspace switching** — entering kitchen mode auto-picks the first kitchen with no indication.
8. **No partial-save on Execute** — actuals are lost if the tablet locks mid-entry; the order already shows in_progress with no data.
9. **Approve step is ambiguous** — Fulfill works straight from `submitted`, so Approve is optional with no enforced meaning.
10. **Recipe hard-delete** one tap away, despite production history referencing recipes.

### Top improvements
1. ✅ Fix the misleading Complete confirmation (done).
2. Enlarge all row actions to 44px tap-sized labeled buttons — the single biggest tablet win.
3. Add confirmation + persistent result message to Fulfill (name the outlet and item count).
4. Pair each status pill with an explicit next-step CTA ("Scheduled — ready to start").
5. "Save progress" on the Execute screen.
6. Resolve the double navigation model (start with the sidebar "Production Orders" → form mismatch).
7. Gate costing/margin data behind manager/costing roles; simplified recipe view for line staff.
8. Flash "Now in Central Kitchen: {name}" on workspace switch + prominent kitchen badge.
9. Enforce or remove the Approve step (one clear "Prepare & Send" action).
10. Card-per-line layout with large inputs + inline UOM on Execute for narrow screens.

## 3. Central Purchasing (CPU)

**What CPU mode is:** a company-wide toggle (`companies.ordering_mode`) — outlets submit PRs instead of POs, a CPU user consolidates approved PRs by supplier into draft POs, goods flow back out via Stock Transfer Orders.

### Pain points
1. **The mode switch is hidden** in the "PO Approvers" page; the Central Purchasing settings card only appears *after* the mode is on — chicken-and-egg discoverability.
2. **No confirmation/impact summary** when flipping the mode — it instantly changes what every outlet can do.
3. **Jargon with no glossary** — CPU, consolidate, PR→PO, via_cpu/direct_to_outlet.
4. **Silent line-dropping in consolidation** — PR lines with no preferred supplier are skipped with only an after-the-fact error; the preview shows a "No Supplier" group that produces nothing.
5. **Kitchen-sourced items vanish from the preview** (routed to production orders) with no note.
6. ✅ **Misleading empty-CPU error** — submitting without a CPU said "Select at least one purchase request". *Fixed: now says "Choose a Central Purchasing Unit (CPU) to consolidate into."*
7. **Two preview fidelities** (sidebar preview vs "Customize & Review") with unclear roles.
8. **No outlet-facing guidance** that ordering became a two-step request → consolidate flow.
9. **Dense CPU create/edit modal** with buried outlet-reassignment side effects.
10. **Draft-PO next step unstated** — consolidation creates *drafts* but the flash just says "created".

### Top improvements
1. Pre-flight validation on the consolidation preview: highlight no-supplier lines, show "2 items will be skipped", offer to assign a supplier. *(Data already computed.)*
2. ✅ Fix the misleading empty-CPU error (done).
3. Move/duplicate the Ordering Mode toggle into a clearly named "Purchasing Mode" card visible in both modes.
4. Confirmation + impact summary modal when switching modes.
5. Success message "N draft POs created — review and send them" with a deep link.
6. "X items routed to kitchen production" note in the preview.
7. A 3-step how-it-works strip on the Consolidate page.
8. Unify the two preview modes into one always-editable review.
9. Empty-state CTA when CPU mode is on but no CPU exists.
10. Section the CPU modal (Details / Delivery / Outlets served / Team) with inline reassignment warnings.

**Wave 1 — copy & guidance (days):** Procurement #1/#5/#6/#9, Kitchen #4 hints, CPU #5/#7/#9. Pure copy/empty-state changes, zero behavioral risk, biggest comprehension gain for non-accounting users.

**Wave 2 — feedback & safety (days):** Procurement #3 (what-happens-next panels), Kitchen #2/#3 (tap targets + Fulfill confirm), CPU #1 (pre-flight validation).

**Wave 3 — structural (week+):** status steppers, Advanced toggle on PO form, kitchen navigation unification, CPU preview unification, role-gated costing data.
